KOEN 맛집 공개등록 + 관리자 삭제 버전 - Firebase 최초 설정
========================================================

이번 버전은 관리자 이메일을 HTML/JS에 고정하지 않습니다.
Firebase Authentication에는 본인이 실제 사용하는 이메일을 관리자 계정으로 등록하면 됩니다.

1. 이메일/비밀번호 로그인 확인
--------------------------------
Firebase Console > Authentication > 로그인 방법
> 이메일/비밀번호가 "사용 설정됨"이면 완료입니다.

2. 관리자 사용자 1개 생성
-------------------------
Firebase Console > Authentication > 사용자(Users) > 사용자 추가

이메일: 본인이 실제 사용하는 이메일 주소
비밀번호: 맛집 삭제에 사용할 관리자 비밀번호

※ koen-admin@koen.local 같은 고정 이메일을 사용할 필요가 없습니다.
※ 이메일과 비밀번호는 소스코드에 저장되지 않습니다.

3. 생성된 관리자의 UID 복사
----------------------------
Authentication > 사용자 목록에서 방금 만든 사용자의 UID를 복사합니다.
UID는 이메일과 별개의 긴 영문/숫자 문자열입니다.

4. Realtime Database에 관리자 UID 등록
----------------------------------------
Firebase Console > Realtime Database > 데이터(Data)
최상위에 아래 구조를 1개 추가합니다.

admins
  └─ [복사한 UID] : true

예시
admins
  └─ aBcDeFg123456789 : true

※ [복사한 UID] 부분에는 실제 Authentication UID를 넣습니다.
※ 값은 문자열 "true"가 아니라 Boolean true로 넣는 것을 권장합니다.

5. Realtime Database Rules 적용
--------------------------------
Firebase Console > Realtime Database > 규칙(Rules)
이 ZIP의 database.rules.json 내용을 전체 복사하여 붙여넣고 게시(Publish)합니다.

이 Rules의 핵심 동작
- 맛집 조회: 누구나
- 새 맛집 등록: 누구나
- 기존 맛집 수정: 누구나
- 맛집 삭제: admins/<로그인UID> = true 인 관리자만
- 별점/한줄후기: 기존처럼 누구나 사용
- 관리자 화면/댓글 관리: 관리자 UID 확인

6. 관리자 이메일 사용 방식
----------------------------
관리자 페이지에 처음 로그인할 때 실제 관리자 이메일 + 비밀번호를 입력합니다.
로그인 성공 후 이메일만 현재 브라우저 localStorage에 저장됩니다.
비밀번호는 저장하지 않습니다.

따라서 같은 브라우저에서는 이후 맛집 삭제 시 기본적으로 비밀번호만 입력하면 됩니다.
다른 PC/휴대폰에서는 최초 1회 관리자 이메일을 다시 입력해야 합니다.

7. 기존 config/adminPassword 정리
---------------------------------
예전 버전의 Realtime Database에 config/adminPassword 값이 남아 있다면 삭제해도 됩니다.
이번 버전은 config/adminPassword를 전혀 사용하지 않습니다.

8. 배포
-------
위 설정이 끝나면 ZIP 안의 파일을 기존 koen-food-map 폴더에 덮어쓰면 됩니다.
메인 파일 이름은 index.html 입니다.
